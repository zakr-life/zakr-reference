# models/sleep_staging/

Implements Addendum 2 §E ("Sleep-state monitoring and physician
informing"). Pure Python 3 standard library — no numpy/TensorFlow/sklearn
install required, mirroring `models/training/`'s and `models/export/`'s
discipline exactly, applied to a second, independent classifier.

```
python3 train_sleep_classifier.py
(cd evaluation && python3 evaluate.py)
python3 export_model.py
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Generates synthetic overnight EEG+IMU data -> subject-level split ->
trains a 5-class (Wake/N1/N2/N3/REM) classifier on motion-clean epochs ->
evaluates held-out accuracy + a confusion matrix + an artifact-robustness
slice -> int8-quantizes with a latency/size budget gate -> writes
`model_card.md`.

**All data is synthetic** (`data_provenance: "synthetic"` on every
record) — see `synthetic_overnight_eeg.py`'s module docstring and
CLAUDE.md §12.3: no real overnight session data exists yet for a device
that hasn't been prototyped. See `model_card.md` (generated by the
pipeline) for the honest accounting of what the measured accuracy does
and doesn't establish.

## The one rule for this subsystem (Addendum 2 §E)

> Sleep monitoring is sensing, scoring, and reporting only. It adds zero
> new stimulation authority. The sleep-stage classifier's output type has
> no field that can reach the stim-command hard clamp or the interlock
> chain — this is a structural fact about the data type, not a policy
> that could be bypassed by a future change.

This package has **zero** dependency on, import of, or function call
into `firmware/core1_inference_radio/inference/stim_command_clamp.h`,
`firmware/core0_safety_signal/safety/interlock_status.h`, or
`firmware/core0_safety_signal/safety/charge_balance.h`, and its output
type (a stage label + a confidence score) has no field that could ever
be passed to any of them. This is mechanically proven, not just claimed
in this README:

```
python3 -m unittest tests.test_no_stimulation_coupling -v
```

That test statically scans every `.py` file in this package (outside
`tests/`) for identifiers that would suggest stimulation coupling (`stim`,
`clamp`, `interlock`, `dac`, `current_mA`, `charge`, `enable`, `permit`),
checks no import ever reaches into `firmware/`, and checks the exported
model artifact's field names directly. It is the sibling of
`app/tests/sleepReport.test.js`'s no-diagnostic-language check and
`firmware/core1_inference_radio/sleep/tests/`'s equivalent C-side
structural check — three independent, mechanical proofs of the same rule
at three different layers of the stack.

## Layout

- `synthetic_overnight_eeg.py` — synthetic overnight EEG+IMU epoch
  generator (subjects -> nights -> 30s epochs), with a stage-dependent
  band-power signature and a Markov-chain stage sequencer so a generated
  night looks like a plausible hypnogram, not shuffled noise. Every
  record carries `data_provenance: "synthetic"`.
- `features.py` — feature extraction (band power per channel + IMU
  movement magnitude) and motion-artifact-contaminated-epoch rejection,
  same discipline as `models/training/features.py`.
- `split.py` — subject-level (never epoch-level) train/val/test split,
  with an explicit no-leakage assertion re-checked independently by
  `evaluation/evaluate.py` before it reports any number.
- `softmax_classifier.py` — the same small, auditable multinomial
  logistic-regression classifier used for the state classifier
  (`models/training/softmax_classifier.py`), sized for a Cortex-M33
  inference budget.
- `train_sleep_classifier.py` — end-to-end training entry point.
- `evaluation/evaluate.py` — held-out accuracy, confusion matrix, a
  separately-reported artifact-robustness slice on motion-contaminated
  epochs the model never trained on, and an independent subject-leakage
  re-check. Writes `evaluation/evaluation_report.json`.
- `export_model.py` — int8 symmetric quantization, a latency/size budget
  gate that fails the build if exceeded, and `model_card.md` generation.
- `tests/` — unit tests for every module above, plus
  `test_no_stimulation_coupling.py` (see above).

## Reporting is wellness-framed, not diagnostic

This classifier's output feeds two consumers, neither of which is
allowed to make a diagnostic claim (Addendum 2 §E):

- `app/mobile/src/state/sleepReport.js` and
  `app/mobile/src/screens/SleepReportScreen.tsx` — a plain-language,
  wellness-framed app report with a persistent, non-dismissable
  disclaimer and an automated string-content test
  (`app/tests/sleepReport.test.js`) that fails the build if any of the
  screen's copy contains diagnostic-sounding language.
- `cloud/clinician-portal/sleepTrend.js` — a clinician-configurable
  threshold that adds a night to a **human-reviewed** portal queue.
  `TODO(OI-10)`: real-time automated physician alerting is explicitly out
  of scope; this is a queue a person reviews, never a push/SMS/pager.

## Known limitations (see `model_card.md` for the generated, numeric version)

- Synthetic data only; no clinical validation of any kind.
- Wellness/descriptive use only — this is NOT a diagnostic sleep-disorder
  classifier and does not detect, screen for, or rule out apnea,
  insomnia, or any other condition.
- Linear (softmax) classifier, matching the state classifier's
  pipeline-completeness-first philosophy, not a claim of clinical
  sufficiency.
- Channel count (4 EEG) matches OI-1's current placeholder figure.
