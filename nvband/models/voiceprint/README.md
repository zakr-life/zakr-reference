# models/voiceprint/

Implements Addendum 2 §B ("Voiceprint"). Pure Python standard library
only (no numpy/scikit-learn), matching `models/training/`'s and
`models/export/`'s dependency-free discipline.

```
python3 -m unittest discover -s models/voiceprint/tests
python3 models/voiceprint/export_model.py
```

## Layout

- `synthetic_voice.py` — generates synthetic per-subject "utterance"
  feature vectors DIRECTLY IN FEATURE SPACE (never synthesized
  waveforms/audio — see module docstring for why). Every record carries
  `"data_provenance": "synthetic"`.
- `enrollment.py` — averages exactly 3 synthetic utterance feature
  vectors into one template, per Addendum 2 §B's enrollment protocol.
- `verify.py` — cosine-similarity **1:1** verification against exactly
  one claimed identity's template. Deliberately has no 1:N search/
  identification function anywhere in the file — see its docstring and
  `tests/test_verify.py`'s structural check for that invariant.
- `export_model.py` — int8-quantizes an enrollment template, benchmarks
  the on-device verification comparison path against a small named
  latency/size budget (fails the build via `sys.exit(1)` if exceeded),
  measures (does not hand-tune) false-accept/false-reject rates on
  held-out synthetic subjects, and writes `model_card.md`.
- `model_card.md` — generated by `export_model.py`; regenerate it by
  running that script rather than hand-editing.
- `tests/` — `unittest` coverage for enrollment averaging, 1:1
  verification correctness (same-subject above threshold, different-
  subject below), and the export budget gate.

## What this is used for

An optional secondary identity-confirmation factor during pairing/
re-pairing or a high-risk app action — never a replacement for
secure-element attestation (CLAUDE.md §7), never a path into
stimulation or the interlock chain (CLAUDE.md §0.1, Addendum 2 Rule 0).

## What's not included in this pass

Real acoustic feature extraction from raw PDM audio — this pipeline
starts from synthetic feature vectors, not synthesized audio, because
the on-device extractor that would turn
`firmware/core1_inference_radio/audio/mic_capture.c`'s sample buffer
into this same feature representation is a firmware/model integration
task not yet performed (see that directory's README, "Not included in
this pass"), in the same honest category as the existing "TinyML runtime
integration is not done" item in `STATUS.md`.
