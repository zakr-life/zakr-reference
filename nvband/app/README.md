# app/

Implements CLAUDE.md §5 (companion mobile app). React Native + TypeScript.

Run the pure-logic test suite (no RN toolchain/emulator required — these
are plain Node modules tested with Node's built-in test runner):

```
node --test app/tests/*.test.js
```

25 tests covering: session state machine (STOP always available, no
local optimism, no confirmation gating), consent defaults (both off),
BLE attestation command gating (mirrors firmware's policy independently),
caregiver adherence computation, and the OTA auto-apply gate.

## Layout

- `mobile/src/state/` — pure logic modules, the actual behavior
  contracts this app makes. Read these before the screens; the screens
  are thin renderers over this state.
- `mobile/src/ble/` — attestation command gating (mirrors
  `firmware/core1_inference_radio/ble/attestation.c` independently, by
  design — see the module's header comment for why duplication here is
  deliberate).
- `mobile/src/screens/` — React Native screens. Not executable in this
  pass (no RN toolchain/emulator in this environment) but structurally
  real, wired to the tested state modules above rather than inlining
  logic in JSX.
- `design-system/` — `AccessibleButton`, `StatusLedIndicator`: shared
  with the clinician portal per CLAUDE.md §2's repo layout.
- `tests/` — the 25 Node-native tests referenced above.

## Not included in this pass

- Actual BLE transport (`react-native-ble-plx` wiring to real GATT
  characteristics) — depends on the UUID table
  (`firmware/core1_inference_radio/ble/gatt_services.h`, also not yet
  generated) and is mechanical once that exists.
- Navigation wiring (`App.tsx`, `@react-navigation` stack) — trivial
  once the screen set above is final; omitted rather than filled with an
  unreviewed guess at the navigation structure.
- iOS/Android native project files (`ios/`, `android/`) — generated by
  `npx react-native init`/Expo tooling, not hand-authored source.
